Verdict (A4): NEGATIVE — both countermeasures stay off.
 * The clipping COST is real and now measured: matched uint8 clipping
   loses -1.7 dB PSNR(HH) / -1.5 dB PSNR(HV) vs the unclipped substrate
   (noclip-final vs clip-final). The 8-bit source data genuinely limits
   the pipeline.
 * But MASKING the saturated pixels out of the data term makes it WORSE
   (clip-sat: -1.6 dB below clip-final on HH; RMSE on the bright top-1%
   rises 56.5 -> 74.6): a clipped target is a biased-but-informative
   lower bound, while NO target lets the regularizers pull bright
   structures down. Real patch confirms: ENL-ROI jumps (1.20 -> 1.80)
   exactly because bright pixels get flattened; EPI(HV) drops
   0.656 -> 0.583.
 * npy+sat (full-range float amplitude) is broken outright (ENLr 0.11,
   EPI(HV) 0.31): the 99th-percentile normalization + clip(0,5) cannot
   accommodate the heavy bright tail (max 16935 vs uint8-clip ~274) —
   the amplitude-domain pipeline needs the compressed dynamic range.
 * Right future fix (not implemented): treat saturated pixels as CENSORED
   observations (target >= clip value, one-sided loss) instead of
   excluding them; and/or log-domain training to absorb the dynamic
   range. Recorded as an open item.
